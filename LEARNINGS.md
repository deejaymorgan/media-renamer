# Learnings

Lessons and decisions, one line each, newest first. Kept deliberately small.

- 2026-08-01 — Decision: the app stays in SwiftUI — no NSViewRepresentable bridges to AppKit for controls. Chosen over bridging NSSegmentedControl, which would have bought a glyph legend in the toolbar picker and equal segment widths. Consequence: where SwiftUI cannot render something, accept it rather than reaching for AppKit, and solve the underlying need on a different surface.
- 2026-08-01 — This repo has several worktrees with identical relative paths, and the shell's cwd can silently reset to the main checkout mid-session: build and run with absolute paths to the worktree. A wrong-tree build still succeeds and still launches, so "it built and ran" is not evidence you exercised your edits — confirm against something visibly different in your version.
- 2026-08-01 — To settle spacing inside a small control, tint each child's background and read the frames off a screenshot — a screenshot of a toolbar item is below the resolution the question needs, and eyeballing it produced two wrong "fixed" claims this round. That trick gave macOS 26's numbers in a minute: the item's glass container insets contents ~7pt, and a default-styled button's frame is ~7pt wider than its glyph on each side, so padding stacks only on the trailing edge.
- 2026-08-01 — Ask before assuming the app can't be run: Daniel granted computer-use access this round after declining in earlier ones. Offscreen probes still can't answer everything — an off-screen window never runs the toolbar's overflow pass, so NSToolbar.visibleItems reports every item visible at every width, which looks like a pass and means nothing.
- 2026-08-01 — .listRowBackground fills the whole row rect, but a sidebar row's selection capsule is inset ~10pt horizontally with an ~8pt corner radius, so any row background drawn to signal hover lands wider and squarer than the selection beside it. These are system metrics, not published ones — match them against a running window.
- 2026-08-01 — A macOS segmented Picker takes one of title *or* image per segment, never both: Label renders icon-only, Label + .labelStyle(.titleAndIcon) renders text-only, and HStack { Image; Text } is flattened so the glyph becomes its own extra segment. All three built and read off a running window. Glyph + word there needs an AppKit NSSegmentedControl bridge; don't retry it with label styles.
- 2026-08-01 — Merging parallel UX sessions: a clean auto-merge is the warning, not the all-clear. Two branches each deleted a surface while silently relying on the surface the other was deleting (rows stopped stating their layout because the toolbar always does; the toolbar only always does because of a sidebar cap the other branch added), and git merged them without a conflict precisely because neither ever opened the other's region. Diff the merged tree against BOTH parents and read for semantic collisions — and grep every branch's strings for behaviour the other branch removed, since stale help text is where cross-stream ownership breaks first.
- 2026-08-01 — ImageRenderer/GeometryReader probes settle SwiftUI layout questions headlessly, but AppKit-backed controls (segmented Picker → NSSegmentedControl, List) do not rasterise through them — they come out as a blank placeholder and their measured size is not to be trusted. Probe pure-SwiftUI geometry; anything NSView-backed still needs eyes on a running build.
- 2026-08-01 — A SwiftUI Menu only lays its label out as SwiftUI content under .menuStyle(.button) + .buttonStyle(.plain); .borderlessButton — and .button with the default button style — hand the label to AppKit, which drops its custom rendering and decouples the click target from what is drawn. Overlaying a clear-Rectangle Menu on the chip to dodge that collapsed the layout chip's hit area to 6×14pt inside a 79×17pt capsule, since a bare Shape has no intrinsic size (10×10 ideal). Make the drawn view the label, and test any construction by planting a GeometryReader in it — if it never reports, the label is not yours.
- 2026-07-31 — On macOS 26 a toolbar item's glass container becomes its control's own frame: give each ToolbarItem one system control, never a caption hand-composed beside it, and don't use .buttonStyle(.borderless) there (it collapses the item to 14pt beside native 36pt ones).
- 2026-07-31 — A fresh worktree spawns at main and contains no notes/ (gitignored): check HEAD before trusting file:line references, and hand off with an explicit base commit plus absolute paths to any brief.
